# Host adapter contract

`createTightbeamAdapter(transport, profile)` has no React or DOM dependency. `adapter.open(sessionKey)` returns a runtime with immutable snapshots, `subscribe`, `loadOlder`, `send`, `retrySend`, `rebuild`, and `dispose`. A host can test this boundary without mounting a component. The supplied `ChatTransport` is a semantic boundary: it decodes an elected backend's wire frames into canonical records while the host owns credentials and authenticated connection setup. The package ships a [source-backed public 0.1.9 wire mapping](public-019-profile.md) for build `2887` and later on the same API line and protocol. The profile records the exact observed identity for correlation, while a later build number or different full source SHA alone does not reject an in-floor target.

The profile checks the exact observed source/build identity once per transport lifetime and requires eight capabilities, including authoritative turn provenance. `inspectTarget` establishes the identity and each capability against the elected compatibility floor; transcript recovery reuses this observation while establishing a fresh Firehose subscription and history snapshot. A generic version label or `/version.protocolVersion` alone does not prove protocol-2 Firehose readiness. The shipped fixture profile is identified as `fixture:local-memory-v1`; it is usable only with the local synthetic transport.

`openChanges` resolves only after approved human authentication and a selected-session, protocol-2 `subscription_ready`. The public transport filters one selected-session connection for `message.created`, `session.`, `turn.started`, and `turn.ended` notices. It sends canonical notices through `onNotice` and reports disconnect, missed heartbeat, sequence doubt, overflow, or revocation through `onDoubt`. The host's decoder maps exact wire resource identities, versions and supported notices into `ChangeNotice`; it must not fabricate transition entries from free text or duplicate canonical markers from a transition-only event. Unknown event kinds are ignored after the transport accounts for their sequence; only actual connection or continuity doubt requests recovery. `readTail` returns a bounded newest slice in chronological order. `readOlder` accepts the opaque cursor verbatim and returns the exclusive preceding slice. Both expose authorized retained **human** history, regardless of agent-context boundaries, including pre-reset rows and recorded switches.

`proveCoverage` is the target-specific consistency proof that a session/tail snapshot and the finite notices buffered after subscription readiness form a closed candidate. It must reject missing or ambiguous coverage. The released profile relies on selected-session subscription readiness before REST reads, retained append-only transcript rows, and versioned notices. Session and turn records update their local state without rebuilding the transcript. Wake and unknown event kinds still participate in transport sequencing but do not trigger reads, reject coverage, or rebuild the snapshot. Turn activity captions use supported live turn notices; turn collections, exact turn/message detail, and role reads are not part of transcript assembly. Tool-call display is enabled by default when supported. The existing Tool calls control turns it off or on; while off, Chat performs no tool-call subscription or history read. This overlap proof is source-backed for the elected profile; it is not a server watermark or durable replay promise. Returning `true` without evidence is valid only for the single-process in-memory fixture.

Canonical message records retain ID, session, sequence, row version, role, sender, content, optional `messageType`, attachments, client/device correlation, and a `raw` copy of all supplied metadata/provenance. Turn records are consumed only from supported live notices for active captions; the renderer does not perform turn, trigger-message, or origin-name REST lookups. Transition records come from canonical marker messages and retain their actual identity, order, and changed harness/model details. The transport must document the exact source projection and its ordering across pages. A `clearedThroughSeq` agent boundary is never a lower visibility bound or a deletion notice. Only a verified canonical delete with a row version removes a row.

`sendHuman` is the distinct human `/ws` post path and resolves to a correlated accepted, refused or uncertain outcome. Its host implementation must preserve session/device/client ID/content for server deduplication, reject different-content ID conflicts, and never turn an uncertain outcome into a fresh ID automatically. The runtime reconciles against a canonical row only when session, device, and client ID all match. A real transport needs a demonstrated human principal, approved HTTPS/WSS or equivalent browser route, and a host-owned way to signal principal changes without exposing credential bytes to the component.

The older `d33c510f` source snapshot lacked the required backward paging and structural marker projection. The exported profile targets the reviewed 0.1.9 compatibility floor described above. Synthetic tests and simulated browser traffic do not establish live gateway/browser acceptance; that still requires real responses with an approved human principal and reachable matching gateway. No fixture result can fill that evidence gap.
