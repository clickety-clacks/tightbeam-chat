# Host adapter contract

`createTightbeamAdapter(transport, profile)` has no React or DOM dependency. `adapter.open(sessionKey)` returns a runtime with immutable snapshots, `subscribe`, `loadOlder`, `send`, `retrySend`, `rebuild`, and `dispose`. A host can test this boundary without mounting a component. The supplied `ChatTransport` is a semantic boundary: it decodes an elected backend's wire frames into canonical records while the host owns credentials and authenticated connection setup. The browser transport validates the responses and connections Chat uses. It does not gate on release version, build number, source stamp, or protocol metadata. See the [Gateway wire profile](public-019-profile.md) for endpoint and event details.

The browser profile declares the eight capabilities its transport implements, including authoritative turn provenance. `inspectTarget` returns that stable backend profile without probing release metadata. Chat validates each REST response and Firehose frame when it uses that endpoint or connection, and surfaces the operation's actual error. Transcript recovery establishes a fresh Firehose subscription and history snapshot. The Firehose subscription itself negotiates protocol 2. The shipped fixture profile is identified as `fixture:local-memory-v1`; it is usable only with the local synthetic transport.

`openChanges` resolves only after approved human authentication and a selected-session, protocol-2 `subscription_ready`. The public transport filters one selected-session connection for `message.created`, `transition.recorded`, `session.`, `turn.started`, and `turn.ended` notices, and adds a `rail.denied` subscription on that same connection filtered by the selected session principal. It sends canonical notices through `onNotice` and reports disconnect, missed heartbeat, sequence doubt, overflow, or revocation through `onDoubt`. The host's decoder maps exact wire resource identities, versions and supported notices into `ChangeNotice`; it must not fabricate transition entries from free text or duplicate canonical markers from a transition-only event. Unknown event kinds are ignored after the transport accounts for their sequence; only actual connection or continuity doubt requests recovery. `readTail` returns a bounded newest slice in chronological order. `readOlder` accepts the opaque cursor verbatim and returns the exclusive preceding slice. Both expose authorized retained **human** history, regardless of agent-context boundaries, including pre-reset rows and recorded switches. Rule-denial observations are live-only until the Gateway history capability is served and accepted; Chat keeps an observed denial across reconnect but neither recovers missed denials nor claims reload persistence.

`proveCoverage` is the target-specific consistency proof that a session/tail snapshot and the finite notices buffered after subscription readiness form a closed candidate. It must reject missing or ambiguous coverage. The browser profile relies on selected-session subscription readiness before REST reads, retained append-only transcript rows, and versioned notices. Session and turn records update their local state without rebuilding the transcript. Wake and unknown event kinds still participate in transport sequencing but do not trigger reads, reject coverage, or rebuild the snapshot. Active-turn captions use only turn records delivered on the current live subscription; no turn, trigger-message, or origin-name read is made to build them. The caption clears when freshness is lost and returns only when the healthy subscription delivers another turn record. Chat enables tool-call display automatically when the optional stream and history are supported; the conversation surface has no Tool calls switch. Integrations can still disable tool calls through the runtime API, in which case Chat performs no tool-call subscription or history read. If the history route is unavailable, Chat keeps the conversation usable and does not show a tool-history warning for that unsupported route. This overlap proof is not a server watermark or durable replay promise. Returning `true` without evidence is valid only for the single-process in-memory fixture.

Canonical message records retain ID, session, sequence, row version, role, sender, content, optional `messageType`, attachments, client/device correlation, and a `raw` copy of all supplied metadata/provenance. Turn records are consumed only from supported live notices for active captions; the renderer does not perform exact turn, trigger-message, or origin-name REST lookups. Transition records come from canonical marker messages and retain their actual identity, order, and changed harness/model details. The transport must document the exact source projection and its ordering across pages. A `clearedThroughSeq` agent boundary is never a lower visibility bound or a deletion notice. Only a verified canonical delete with a row version removes a row.

`sendHuman` is the distinct human `/ws` post path and resolves to a correlated accepted, refused or uncertain outcome. Its host implementation must preserve session/device/client ID/content for server deduplication, reject different-content ID conflicts, and never turn an uncertain outcome into a fresh ID automatically. The runtime reconciles against a canonical row only when session, device, and client ID all match. A real transport needs a demonstrated human principal, approved HTTPS/WSS or equivalent browser route, and a host-owned way to signal principal changes without exposing credential bytes to the component.

The conversation surface invokes `markReadPosition` for the selected conversation when it opens and becomes ready, when Chat accepts Mike's send (regardless of its later outcome) or he requests a retry, when he manually scrolls (including tapping jump to latest), and when the visible page returns with that conversation selected. Automatic scrolling, passive replies, hidden-page activity, rejected sends, and local settings do not trigger a marker attempt. Each attempt uses the newest canonical message and the scope key `<exact full session key>:session-read-position`. The marker transport reads and conditionally writes that exact scope key, preserving its numeric forward-only position after conflicts. It stays unavailable unless the host explicitly declares an existing compatible user-device route. That declaration must match the credentials used by its authorized `fetch`; Chat does not provision or infer credentials. Targets without the marker route keep conversation loading and interaction behavior unchanged.

The historical source comparisons in this repository document how the wire mapping evolved; they do not define a minimum release identity. Synthetic tests and simulated browser traffic do not establish compatibility with a released Gateway. That evidence requires real responses from the version under test in an isolated environment. Deployed-host browser acceptance remains separate.
