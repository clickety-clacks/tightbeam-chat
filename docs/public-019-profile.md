# Gateway wire profile

The wire mapping was initially compared with two earlier source snapshots ([first](https://github.com/clickety-clacks/tightbeam/tree/0198c918dbd86861297aca19e7c3dc583943bbac), [later](https://github.com/clickety-clacks/tightbeam/tree/8433d22fdf86027d62a34e9923501775225813ad)). Those comparisons are historical references, not a compatibility floor or runtime release gate. Chat does not use `/version` to decide whether to load; it checks the actual REST envelopes and fields it consumes, and the authenticated Firehose and human WebSocket exchanges. The Firehose subscription uses protocol 2. The observed release identity is not used to decide compatibility.

- [`router.ex`](https://github.com/clickety-clacks/tightbeam/blob/8433d22fdf86027d62a34e9923501775225813ad/lib/tightbeam/wire/router.ex) exposes session detail and bounded message history used to open and page a conversation. The client does not call exact turn/message, or role-detail routes to assemble transcript rows. Active activity captions use only supported `turn.started` and `turn.ended` notices on the selected-session connection; Chat does not make a turn-history read to populate the caption.
- [`router.ex`](https://github.com/clickety-clacks/tightbeam/blob/8433d22fdf86027d62a34e9923501775225813ad/lib/tightbeam/wire/router.ex) exposes `GET /api/sessions/:sessionKey` and `/api/sessions/:sessionKey/messages?limit=50&tail=true`. The transcript collection has `items` and `page.oldestCursor`/`hasMoreBefore`. History uses opaque `before` cursors unchanged. The newest bounded slice is emitted in ascending order, displayed chronologically with the viewport at its newest end. Upward scrolling loads earlier rows without treating an agent context reset as a visibility cutoff.
- [`state_resources.ex`](https://github.com/clickety-clacks/tightbeam/blob/8433d22fdf86027d62a34e9923501775225813ad/lib/tightbeam/state_resources.ex) emits stored `marker: {kind, from, to}` on marker rows. `harness-switch`, `model-retune`, and `session-restart` remain ordered canonical transitions. Chat receives them as canonical message rows and renders their short transition summaries in sequence. Raw message metadata remains available to the host renderer.
- [`change_socket.ex`](https://github.com/clickety-clacks/tightbeam/blob/8433d22fdf86027d62a34e9923501775225813ad/lib/tightbeam/wire/change_socket.ex) authenticates `/ws/changes?protocolVersion=2`, then completes selected-session subscription before `subscription_ready`. The runtime waits for readiness before REST reads and merges buffered versioned notices with retained rows. Its transcript connection filters `message.created`, `transition.recorded`, `session.`, `turn.started`, and `turn.ended` for the selected session, with a separate `rail.denied` subscription filtered by the acting principal `session:<selected key>`; transition markers arrive as canonical message rows. Session and turn notices update local state without rebuilding the transcript, and active captions use only turn records delivered on the current subscription. Rule-denial lines are live-only until Gateway history is served and accepted. Wake and unknown event kinds still consume sequence but do not cause extra reads, reject snapshot coverage, or replace the transcript snapshot. Chat automatically displays tool calls when the optional stream and history are supported, without a Tool calls switch in the conversation surface. An integration can disable them through the runtime API, which stops the tool-call subscription and history reads; if tool-call history is unsupported by the Gateway, Chat keeps the conversation usable without a tool-history warning. This client overlap is not a server snapshot watermark or durable event replay. Sequence gaps, disconnects, and missing heartbeats trigger a fresh subscription and REST rebuild.
- [`socket.ex`](https://github.com/clickety-clacks/tightbeam/blob/f724fc41089335887e6eb76bfd89d9b6d50db7cd/lib/tightbeam/wire/socket.ex) authenticates human `/ws` with a paired device token, then emits `sync_complete`. Sending uses that separate connection and a `c_` client ID. Correlated ack means acceptance, not agent completion. Retry retains the same ID/device/content for gateway deduplication. Session tokens can read their own selected session but cannot send through human `/ws`; org CLI tokens cannot read these routes.

The browser host keeps credentials in memory, sends REST bearer headers and WebSocket auth frames, and checks device/principal identity. It does not treat human replay as canonical history. Its local server forwards selected read routes and WebSocket frames without requiring gateway CORS support; it is a loopback development bridge, not a deployment server.

The surface presents only source-proven human messages and selected-agent replies. A mixed notification batch shows human member content only; non-human payload and the batch wrapper remain hidden, while the original canonical record remains available to reconciliation. Safe Markdown supplies readable headings, emphasis, lists, links, inline and block code, quotes, and tables without activating raw HTML. Tests cover source-shaped responses and browser interaction with a **simulated** gateway; they do not establish acceptance against a live gateway. Production hosting, token persistence, attachment operations, and token streaming are outside this example.
